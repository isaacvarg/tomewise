# `tome vault rebuild`

```
tome vault rebuild
```

Regenerates one Markdown note per session from history, for vault mode (ADR 0009). History stays the source of truth: notes are a view of it, and the same history always gives byte-identical notes.

- Notes go to `<notesFolder>/<subject>/<YYYY-MM-DD>-<session id>.md`, where `notesFolder` is `vault.notesFolder` in `tomewise.json` (default `sessions`) and the date is the day the session started, in the learning home's `timezone`.
- Rebuild overwrites only notes it generated: files whose frontmatter has the line `generatedBy: tomewise`. Any other file, including a learner's file with a note's name, is left alone and listed in the output. Edits to generated notes are overwritten.
- Notes for sessions no longer in history are left in place.
- Exit codes: `0` success, `1` the learning home has problems, `2` bad arguments, no learning home, or vault mode off.

## Note format

```markdown
---
generatedBy: tomewise
subject: "morse-code"
date: 2026-10-30
ref: "lesson:0001-k-and-m"
durationMin: 0.3
attempts: 6
correct: 5
wrong: 1
skipped: 0
lesson: "0001-k-and-m"
---

# Morse code: lesson 0001-k-and-m

Lesson 0001-k-and-m on 2026-10-30, 0.3 min. 6 attempts: 5 correct, 1 wrong, 0 skipped (83%).

Practised: letter-k, letter-m.

Generated by Tomewise from history; edits are overwritten by `tome vault rebuild`.
```

| Field | Meaning |
|---|---|
| `generatedBy` | Always `tomewise`; marks the note as generated |
| `subject` | Subject id |
| `date` | Day the session started |
| `ref` | What the session ran: a lesson, drill, quiz or exam |
| `durationMin` | Session time in minutes, to one decimal: the `session.end`'s `duration`, or the span to the session's last event if it never ended |
| `attempts`, `correct`, `wrong`, `skipped` | Attempts in the session, in total and by outcome |
| `lesson` | The lesson id for a lesson session, otherwise `null` |
