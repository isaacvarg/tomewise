# `tome vault rebuild`

```
tome vault rebuild
```

Regenerates one Markdown note per session from history, and a Markdown copy of each subject's curriculum, for vault mode (ADR 0009). History stays the source of truth: notes are a view of it, and the same history always gives byte-identical notes.

- Notes go to `<notesFolder>/<subject>/<YYYY-MM-DD>-<session id>.md`, where `notesFolder` is `vault.notesFolder` in `tomewise.json` (default `sessions`) and the date is the day the session started, in the learning home's `timezone`.
- Rebuild overwrites only notes it generated: files whose frontmatter has the line `generatedBy: tomewise`. Any other file, including a learner's file with a note's name, is left alone and listed in the output. Edits to generated notes are overwritten.
- Notes for sessions no longer in history are left in place.
- Each subject with a `curriculum.json` gets `subjects/<subject>/curriculum.md`, by the same marker rule. See [Curriculum copy](#curriculum-copy).
- It also writes the sessions Base, `sessions.base`, at the learning home root (see below). The output counts notes and the Base together as vault files.
- Exit codes: `0` success, `1` the learning home has problems, `2` bad arguments, no learning home, or vault mode off.

## Note format

```markdown
---
generatedBy: tomewise
subject: "morse-code"
date: 2026-10-30
ref: "lesson:0001-k-and-m"
durationMin: 0.3
attempts: 6
correct: 5
wrong: 1
skipped: 0
lesson: "0001-k-and-m"
---

# Morse code: lesson 0001-k-and-m

Lesson 0001-k-and-m on 2026-10-30, 0.3 min. 6 attempts: 5 correct, 1 wrong, 0 skipped (83%).

Practised: letter-k, letter-m.

Generated by Tomewise from history; edits are overwritten by `tome vault rebuild`.
```

| Field | Meaning |
|---|---|
| `generatedBy` | Always `tomewise`; marks the note as generated |
| `subject` | Subject id |
| `date` | Day the session started |
| `ref` | What the session ran: a lesson, drill, quiz or exam |
| `durationMin` | Session time in minutes, to one decimal: the `session.end`'s `duration`, or the span to the session's last event if it never ended |
| `attempts`, `correct`, `wrong`, `skipped` | Attempts in the session, in total and by outcome |
| `lesson` | The lesson id for a lesson session, otherwise `null` |

## Curriculum copy

```markdown
---
generatedBy: tomewise
subject: "morse-code"
---

# Morse code: curriculum

## Koch letters

1. Copy K, M, R, S and U: current
   - Lessons: 0001-k-and-m, 0002-r, 0003-s, 0004-the-late-bump
   - Exam: first-five
2. Copy the next five letters: upcoming

Generated by Tomewise from `curriculum.json` and history; edits are overwritten by `tome vault rebuild`.
```

Milestones are numbered in order across units. Each status is the one in `curriculum.json`, replaced by the latest `milestone.status` event for that milestone. With vault mode on, the app also writes the copy when it starts or vault mode is turned on, and rewrites it after a `milestone.status` event, posted or pulled, and after `curriculum.json` changes.

## Sessions Base

`sessions.base` is an [Obsidian Base](https://obsidian.md/help/bases/syntax) over the session notes. `tome init` writes it in vault mode, and `tome vault rebuild` rewrites it.

- It lists notes whose frontmatter has `generatedBy: tomewise` and a `ref`, wherever they sit in the vault. It doesn't filter by folder, so it keeps working if the learning home moves inside the vault, and a vault with two learning homes shows both homes' sessions.
- Two table views: **By subject**, grouped by `subject`, and **By week**, grouped by a `week` formula over `date` (ISO week, such as `2026-W44`, starting Monday whatever `weekStart` says). Both sort newest first and sum `durationMin` and `attempts`.
- The marker is the first line, the YAML comment `# generatedBy: tomewise`. Rebuild overwrites the Base only while that line is there. Delete it to keep your own version; saving view changes from Obsidian's interface may also drop the comment, and then rebuild leaves the file alone.
